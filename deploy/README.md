# exe.dev deployment

Production is live at:

```text
https://push.vhtm.eu
```

The app runs on the existing exe.dev VM:

```text
vhtm-eu / vhtm-eu.exe.xyz
```

## Architecture

```text
client
  -> https://push.vhtm.eu
  -> exe.dev HTTPS proxy, TLS termination
  -> vhtm-eu VM port 8080
  -> Caddy :8080
  -> 127.0.0.1:3001
  -> Next.js Docker container
  -> Postgres Docker container / named volume
```

Current port/domain allocation:

| Hostname       | VM port | Local target     | App        |
| -------------- | ------: | ---------------- | ---------- |
| `push.vhtm.eu` |  `8080` | `127.0.0.1:3001` | Push Padel |

This VM can host multiple small apps. Keep one shared Caddy instance on port `8080`, then allocate a unique localhost port per app, e.g. `3002`, `3003`, etc. Use separate Docker Compose projects and database volumes per app.

Use a separate VM only when an app has materially different security, resource, or lifecycle needs.

## Deploy-on-push

GitHub repo:

```text
https://github.com/Jason-vh/push
```

Workflow:

```text
.github/workflows/deploy.yml
```

Every push to `main`:

1. runs on the self-hosted runner labeled `push-prod`
2. writes `.env.production` from GitHub Actions secrets
3. copies the checkout to `/home/exedev/apps/push`
4. runs Docker Compose from that stable directory
5. applies Prisma migrations during app startup via `npm start`

Required GitHub Actions secret:

```text
POSTGRES_PASSWORD
```

The runner is registered specifically to this repo and managed by:

```text
gh-actions-runner-push.service
```

## Environment variables

Production env shape:

```bash
APP_URL=https://push.vhtm.eu
NEXT_PUBLIC_APP_URL=https://push.vhtm.eu
POSTGRES_PASSWORD=<from GitHub secret>
PUSH_APP_HOST_PORT=3001
COMPOSE_PROJECT_NAME=push
```

`APP_URL` matters for passkeys. Passkeys are origin-bound, so production sign-in/sign-up must happen on `https://push.vhtm.eu`.

## Caddy

Current Caddy shape:

```caddyfile
{
  auto_https off
}

:8080 {
  @push host push.vhtm.eu
  handle @push {
    reverse_proxy 127.0.0.1:3001
  }

  handle {
    respond "No app configured for this host" 404
  }
}
```

`auto_https off` is intentional. exe.dev terminates TLS and forwards HTTP to the VM.

After editing Caddy:

```bash
sudo caddy fmt --overwrite /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

## Operations

SSH into the VM:

```bash
ssh vhtm-eu.exe.xyz
cd /home/exedev/apps/push
```

Check containers:

```bash
docker compose --env-file .env.production ps
```

App logs:

```bash
docker compose --env-file .env.production logs -f app
```

Database logs:

```bash
docker compose --env-file .env.production logs -f db
```

Restart app:

```bash
docker compose --env-file .env.production restart app
```

Restart everything:

```bash
docker compose --env-file .env.production up -d --build --remove-orphans
```

Run migrations manually if needed:

```bash
docker compose --env-file .env.production exec app npx prisma migrate deploy
```

Open a database shell:

```bash
docker compose --env-file .env.production exec db psql -U push -d push_padel
```

Check public site:

```bash
curl -I https://push.vhtm.eu
```

## Adding another app to this VM

1. Pick a new local port, e.g. `3002`.
2. Run that app with Docker Compose bound to `127.0.0.1:3002`.
3. Add a Caddy host route in `/etc/caddy/Caddyfile`.
4. Add DNS `new-app.vhtm.eu CNAME vhtm-eu.exe.xyz`.
5. Register the domain with exe.dev:

```bash
ssh exe.dev domain add vhtm-eu new-app.vhtm.eu
```

Do not change exe.dev's shared port away from `8080`; that port belongs to the VM-level Caddy router.

## One-time rebuild from scratch

If the app needs to be recreated but data should remain:

```bash
cd /home/exedev/apps/push
docker compose --env-file .env.production down
docker compose --env-file .env.production up -d --build
```

If data should be destroyed too, remove the named volume explicitly:

```bash
docker compose --env-file .env.production down -v
```

Be careful: `down -v` deletes the Postgres data volume.
